# VRM 姿势台（vrm-poser）

用 **VRM 归一化人形骨骼** 驱动的网页姿势台：一份姿势 JSON，套到任意 VRM 角色上。

这是"用姿势网站的姿势驱动任意人物"的最小闭环，验证三件事：

1. VRM 能在网页里加载并正确渲染（three.js + `@pixiv/three-vrm`）
2. 姿势只写**归一化骨骼**，因此与模型无关，可跨角色复用
3. 姿势可以完整序列化成 JSON、存下来、再贴回去

---

## 快速开始

```powershell
cd "D:\DeepSeek Harness\vrm-poser"
npm install
npm run dev
```

打开 <http://localhost:5273/>。

> 端口固定为 5273（`--strictPort`）；`npm run build` 后可用 `npm run preview` 看构建产物（5274）。

**注意**：Vite 默认只绑 `localhost`（IPv6 `::1`）。如果浏览器打不开，用 `http://localhost:5273/` 而不是 `127.0.0.1:5273`。

### 动作（待机动画）

面板「动作」区：

| 按钮 | 类型 | 说明 |
| --- | --- | --- |
| 呼吸 / 轻晃 / 挥手 | **程序化** | 直接驱动代理骨骼，不依赖任何文件 |
| 待机A / 待机B | **VMD** | 本项目自己生成的 `.vmd`（`public/motions/`） |
| 载入 .vmd 动作 | 文件 | 播放你自己下载的 MMD 动作 |
| 暂停 / 速度 | — | 播放控制 |

#### 为什么仓库里的待机动作是"自己生成"的

VMD 的骨名是 **Shift-JIS**，浏览器和 Node 都没有内置编码器，没法凭空写出合法文件；
而网上现成的动作多半带"禁止二次配布"，不适合随代码分发。

解决办法：`scripts/make-idle-vmd.mjs` 反查 `mmd-parser` 自带的 `s2uTable`（SJIS → Unicode）
建立编码表，然后**自己生成**待机动作：

```powershell
node scripts/make-idle-vmd.mjs   # 产出 public/motions/idle-breathe.vmd / idle-sway.vmd
```

#### 三个必踩的坑（都写在 `src/vmd.js` 注释里）

1. **VMD 的 position 是位移偏移，不是绝对坐标**。センター 的 rest 位置是 `(0, 0.83, 0)`，
   直接覆盖会让整个人沉到地板下（实测塌 0.8 米，看起来像"腿折了"）。
   正确做法：`bone.position = rest + offset * scale`，且只对 センター/グルーブ/腰 生效。
2. **没被动作覆盖的骨骼要回 rest**（MMD 语义）。否则会保留上一次姿势的残留。
3. **骨骼保持 MMD 坐标系，不要做左手→右手转换**。`pmx-loader` 建的骨骼和 `retarget`
   都在 MMD 空间里算，所以 `parseVmd(buffer, false)` 的原始四元数正好能直接写进
   `bone.quaternion`。一旦传 `true`，旋转轴整体错 ~90°。
4. 生成器里**三个轴都要合成**：早期版本只合成了 rx/ry，`rz` 被丢掉，手臂放不下来。

#### 动作与姿势互斥

动作播放期间，姿势面板会被**锁住**（变灰、`pointer-events: none`），避免"改了没反应"的困惑：

| 状态 | 姿势面板 | 说明 |
| --- | --- | --- |
| 无动作 | 可用 | 正常编辑 |
| 播放中 | **锁定** + 黄色提示 | 点「停止」或直接应用一个姿势即可解锁 |

反过来，**应用任何姿势都会先停掉动作**——`createUI` 的 `onBeforePose` 钩子挂在
`applyPoseData` 的最前面，所以画廊点卡片、预设、镜像、图片生成姿势都不会和动作打架。

#### 想要更多动作

| 来源 | 说明 |
| --- | --- |
| [BOOTH「何もしない」まばたき＆呼吸モーション](https://booth.pm/en/items/6123352) | 作者 かんな，免费的待机/眨眼动作，**按作者条款使用** |
| [bear0830/mmd](https://github.com/bear0830/mmd) | 25 个 VMD，**仓库没有许可证**，只适合自己下载来用，别转发 |

约束和模型一样：**只在本地自己用**，不要二次分发。

### 视线跟随

面板上的「视线跟随」默认开启：鼠标在画面里指哪儿，角色的头和颈就朝哪儿转。

实现要点（三个坑都在 `updateGaze()` 的注释里）：

1. **目标点不能取"射线与过头部平面的交点"**：相机正对头部时交点退化成头骨本身，
   方向向量≈0，`atan2` 会乱跳（实测直接打满 ±42°）。改为取"相机与头部之间 0.5 倍距离"
   的那个点，方向永远朝相机一侧，中心点自然收敛到 0。
2. **叠加必须每帧还原**：`avatar.update()` 是朝目标姿势做阻尼插值的，把旋转乘上去之后
   不还原，下一帧会从叠加后的姿态继续转，实测能滚到 160°。做法是渲染前应用、渲染后 `restoreGaze()`。
3. **改代理骨骼不会动画面**：蒙皮用的是真实 MMD 骨骼，而重定向在 `avatar.update()` 里已经跑完。
   改完 humanoid 代理节点后必须再调一次 `avatar.retarget()`，否则数值对了但模型不动。

角度上限：yaw ±42°、pitch ±26°，头 70% / 颈 30%，阻尼 `dt * 8`。

### 视角：360° 无死角 + 预设

- 轨道相机允许一直转到接近正下方（maxPolarAngle = π × 0.995），minDistance 0.35 可以贴近看
- 相机低于地面时**自动隐藏地板、网格和接触阴影**——否则从下往上看只能看到一块地板
- 滚轮缩放、左键拖动；双击画面重置视角
- 面板里有 6 个一键视角：**正面 / 侧面 / 背面 / 俯视 / 仰视 / 特写**，外加**自动环绕**开关
  - 取景基于骨骼包围盒（`boneWorldPoints`），换模型、换姿势都会跟着变
  - 正俯视/正仰视时方向向量和 up 轴错开一点，否则 `lookAt` 会退化

### 载入文件夹会自己存进 public/models

浏览器不能直接写磁盘，但 `npm run dev` 起的 Vite 本身就是本地 Node 进程，所以加了一个开发期中间件：

```
拖入文件夹
  ↓ POST /__save-model?model=<目录名>&path=<相对路径>   （每个文件一次，二进制 body）
  ↓ Vite 中间件写进 public/models/<目录名>/...
  ↓ POST /__scan → 重跑 scripts/scan-models.mjs
  ↓ 角色库自动刷新，立刻出现新卡片
```

实测：拖入 3 个文件 → `public/models/测试角色/{测试角色.pmx, Texture/...}` 落盘，索引里出现「测试角色」。

**每个用户跑自己的 dev server，就写进他自己的项目目录** —— 不需要额外的服务进程，也不需要文件系统授权弹窗。

安全措施（`vite.config.js`）：

- 只允许写到 `public/models/` 下面
- 目录名过滤 `\ / : * ? " < > |`，相对路径剔除 `.` / `..`，最后再校验绝对路径前缀
- 单文件上限 200 MB

**纯静态部署时**（`node scripts/serve-dist.mjs`，没有中间件）：探测 `/__save-model` 失败 →
自动退回**浏览器收藏库**（IndexedDB），角色库里标「本地收藏」，刷新后仍在，但换电脑/清缓存会丢。

### 模型目录（只放链接，不放文件）

`public/catalog/models.json` 是一份**指路清单**：每条记录某个角色在模之屋的**页面链接**，
点卡片会在新标签打开原页面，用户自己登录、自己下载。

```json
{
  "id": "wuwa-averdia",
  "game": "鸣潮",
  "character": "阿维狄亚",
  "fileName": "",
  "source": "模之屋",
  "sourceUrl": "https://www.aplaybox.com/details/model/EtLbLO00D4aC",
  "author": "",
  "license": "见原页面说明"
}
```

卡片有三种状态：

| 状态 | 判定 | 点击行为 |
| --- | --- | --- |
| **去下载** | 目录有、本机没有、`sourceUrl` 非空 | 新标签打开模之屋页面 |
| **已收藏** | 按 `fileName` / 角色名匹配到本机模型 | 直接加载该模型 |
| **待补链接** | `sourceUrl` 为空 | 提示去补 JSON |

> **法律边界**：只链接页面，不托管、不代理、不直链 `.zip`。
> 直链会绕过对方的登录/点数流程，既是盗链也会被 referer 挡掉。
> 条目的 `author` / `license` 要如实填写，尊重原作者。

#### 半自动导入（不抓取）

目录页右上角「导入条目」：把从模之屋复制的行粘进去，解析成条目。

支持的粘贴格式（都在 `src/catalogImport.js` 里）：

```
刻晴	原神	https://www.aplaybox.com/details/model/xxx     ← 制表符三列
胡桃 | 原神 | https://...                                  ← 竖线
今汐, 鸣潮, https://...                                    ← 逗号
- 散兵 https://...                                         ← 项目符号
https://...                                                ← 只有链接（角色名留空）
```

- 解析出 `角色名 / 游戏 / 链接`，游戏列缺省时用面板上的「默认游戏」
- 同一链接重复粘贴会被去重；没有链接的行报错并跳过
- 导入的条目存在 `localStorage`（`vrm-poser:catalog-extra:v1`），**立刻出现在目录里**
- 「导出完整 JSON」把仓库文件 + 本地新增合并下载，替换 `public/catalog/models.json` 即可落盘

> 刻意不做爬虫：模之屋有反爬，批量抓取也违反其条款。这里只处理用户自己复制的文本。

### 入库闭环：存盘 → 填元数据 → 可编辑可删除

模型存到 `public/models/` 之后，会自动弹出**元数据表单**，把自动猜错的部分改掉：

```
游戏 / 角色 / 服装 / 作者 / 许可 / 标签
  ↓ 写 public/models/<目录>/model.json
  ↓ 重新扫描 → 角色库刷新
```

对应的服务端接口（同样只在 `npm run dev` 下可用）：

| 接口 | 作用 |
| --- | --- |
| `POST /__save-meta?model=<dir>` | 写 `model.json`（字段白名单，避免往仓库里塞任意内容） |
| `POST /__delete-model?model=<dir>` | 删除整个模型目录（同样校验路径前缀），随后重新扫描 |

角色库卡片悬停有 **✎ 编辑元数据** 和 **✕ 删除**：

- 磁盘模型 → 删 `public/models/<目录>/`
- 浏览器收藏 → 删 IndexedDB（提示里会说明区别）

### 服装分组

同一 **游戏 + 角色** 的多个模型合并成一张卡：

```
┌──────────────┐
│   缩略图      │
│ 维琳娜        │  ← 角色名，不再显示"维琳娜（测试礼服）"
│ 绝区零 · 2 套服装 │
│ [默认] [礼服]  │  ← 点哪个加载哪个
└──────────────┘
```

排序时 `outfit === '默认'` 的模型排前面当封面。多套服装时缩略图取封面那套（换姿势/换服装后会自动重烤）。

### 角色库（首屏）

打开页面先看到**角色库**：按游戏分组、可搜索、点卡片直接加载。

数据来自 `public/models/index.json`，由扫描脚本生成：

```powershell
npm run scan        # = node scripts/scan-models.mjs
```

扫描规则：

- 每个 `public/models/<目录>/` 算一个模型（跳过 `batch` / `posedata` / `mediapipe`）
- 目录里有 `model.json` 就用它；没有就按目录名猜游戏和角色名
- 取目录里**最大的** `.pmx`（配件通常比本体小），没有 pmx 再找 `.vrm` / `.glb`

单个模型的元数据（手写，覆盖扫描的猜测值）：

```json
{
  "id": "zzz-weilina",
  "game": "绝区零",
  "character": "维琳娜",
  "outfit": "默认",
  "name": "维琳娜",
  "author": "米哈游 · 社区转换",
  "source": "模之屋",
  "license": "禁止二次配布 / 禁止商用",
  "tags": ["银发", "礼服"],
  "scale": 1,
  "groundOffset": 0.004
}
```

角色卡缩略图**第一次打开该角色时自动烘焙**（离屏渲染 + 透明底），存 IndexedDB，
下次打开直接有图。想重烤就清 `vrm-poser-thumbs` 这个库。

> `model.json` 里的 `scale` / `groundOffset` 目前还没被 loader 消费（每个模型的接地依赖
> `groundClearance` 自动测量），留着是为「每模型独立校正」预留的字段。

### 姿势库画廊

面板底部「打开姿势库画廊」：卡片网格 + 搜索框，点卡片直接应用姿势。

**缩略图是现烤的**：用当前模型 + 当前渲染设置，离屏渲染到 `WebGLRenderTarget`（384×512），
读像素 → 转 PNG → 存 IndexedDB。所以：

- 换模型 → 缩略图自动跟着换（缓存键里带模型标识）
- 改描边/高光/接地 → 缓存键里的渲染版本变，自动重烤
- 不必维护任何静态图片资源

姿势清单在 `public/poses/manifest.json`：

```json
{ "id": "sit", "name": "坐姿", "category": "坐姿", "tags": ["坐", "地面"], "file": "/poses/sit.json" }
```

> 烘焙时会临时改姿势，**结束后一定还原**（`finally` 里恢复姿势 + 根节点高度 + 场景背景）。
> 缩略图要透明底，烘焙期间需要 `scene.background = null`，否则卡片里是深色方块。

### 从图片生成姿势（MediaPipe Pose Landmarker）

面板上的「从图片生成姿势」：选一张参考图（照片或线稿），浏览器内直接跑
`@mediapipe/tasks-vision` 的 PoseLandmarker，拿 33 个 3D 关键点，转成 `vrm-pose/1` 应用到当前模型。

| 依赖 | 位置 | 说明 |
| --- | --- | --- |
| `pose_landmarker_lite.task` | `public/models/mediapipe/` | 5.8 MB，离线可用 |
| WASM 运行时 | `public/models/mediapipe/wasm/` | 从 `node_modules/@mediapipe/tasks-vision/wasm` 拷来 |

**线稿必须先预处理**：检测器是在真实照片上训练的，白底黑线直接喂进去 0 检出。
`src/imagepose.js` 里的 `preprocessToBody()` 把暗线压成深灰、背景提亮，再高斯模糊 6px，
近似出"有体积的人形"，之后才能检出（实测：原图 ✗ / 反色 ✗ / 体块+模糊 ✓ / 强对比 ✗）。

**只取方向、不搬位置**：关键点的绝对坐标属于照片里那个人，直接搬到模型上会把模型拉变形。
`src/img2pose.js` 用「髋线当左右轴、髋→肩当上轴」构造基矩阵，把关键点转到模型空间，
再逐根骨骼用 `setFromUnitVectors(当前方向, 目标方向)` 瞄准 —— 正面/侧面/俯视图都能用。

**置信度着色**：每根骨骼的可信度取定义它方向的两个关键点的 `visibility` 最小值，
低于 0.8 的在骨骼下拉里标 `⚠`，并在面板下方列出彩色 chip，点一下就选中该骨骼去微调。

**多视图融合**：一次可以选多张（同一姿势的不同角度），`fuseViews()` 会融合。
关键在于**不能简单平均**——每个视图的景深轴误差远大于画面内误差，
所以按"该视图视线与各坐标轴的夹角"逐轴加权：视线越接近平行某轴，该轴在这个视图里权重越低。
实测 `front + side + high` 三视图融合后，置信度提示从"2 个关节标黄"变成"全部可用"。

### 姿势编辑闭环（镜像 / 覆盖保存 / 撤销）

姿势文件是静态资源，浏览器写不了盘，所以修改走 **localStorage 覆盖层**：

| 操作 | 行为 |
| --- | --- |
| **镜像** | `mirrorPose()`：左右骨骼互换 + 四元数 y/z 取反 + hips 的 x 取反 |
| **覆盖保存** | 把当前姿势写进 `vrm-poser:pose-overrides:v1`，画廊卡片标「已改」，缩略图自动重烤 |
| **撤销** | 删掉覆盖，回到文件原版 |

缩略图缓存键里带了**覆盖时间戳**，所以改完立刻能看到新图，不用手动清缓存。

> 想真正落盘：控制台执行 `copy(JSON.stringify(JSON.parse(localStorage.getItem('vrm-poser:pose-overrides:v1')), null, 2))`
> 拿到 JSON，替换 `public/poses/` 下对应文件即可。

### 四肢定位与穿模回避

**只控方向不够**：我们的模型手臂比参考白模长，指向同一方向时手会"过头"戳进脑袋。
所以改成 **两骨 IK**：把末端放到参考里的**位置**（按模型/参考的骨长比缩放），
再用余弦定理反解肘/膝，弯曲平面由参考里的中间关节方向决定。

**碰撞回避**：躯干当胶囊、头当球，用骨骼位置估尺寸（不依赖网格）：

```
torsoR = 肩宽 × 0.34      headR = 颈↔头距离 × 0.9      肢体半径 = 0.045
```

IK 解完沿手臂两段采样 7 个点，算到躯干轴/头心的距离；侵入就沿"向外"方向把目标推
`depth × 1.25`，重解，最多迭代 6 次。

> 腿**不做**碰撞回避：大腿根部本来就在躯干半径内，一检测就会把腿推成大劈叉，
> 只保留外展余量（`legOut`）。这是取舍，不是遗漏。



把参考站的一批姿势图批量跑成姿势 JSON，产出在 `public/poses/generated/`，并写进 manifest。

```powershell
# 1) 下载素材（10 组 × 正面/侧面/俯视，约 7 MB）
node 脚本见 scripts/ 里的下载逻辑      # → public/models/batch/<id>/{front,side,high}.png

# 2) 浏览器里跑批量推理（一次性）
#    http://localhost:5273/pose-batch.html → window.__batch

# 3) 关键点 → 姿势 JSON + 更新 manifest
node scripts/batch-topose.mjs
```

实测 10 组：全部检出，视图覆盖 1~3 张。**检出视图越少，姿态越不可信**。

### 躺卧类：检测器基本失效（已实测确认）

对 `P050 侧卧・托腮` 做过穷举：**6 种预处理 × lite/full 两个模型 × 三个视角**：

| 视角 | 结果 |
| --- | --- |
| 正面 | **12/12 全部检不出** |
| 俯视 | **12/12 全部检不出** |
| 侧面 | 4/12 能检出（默认模糊 b6、深色变体） |

结论：**预处理救不了躺姿**——检测器的先验假设是"站立的人"，躺着/趴着的人超出分布。
侥幸检出的结果也会被拉成站姿。

处理方式：`landmarksToPose()` 用**原始关键点**判断躯干是否接近水平（注意不能用模型空间，
那里的"上"是由髋→肩构造的，恒为 +Y），为真则写 `meta.lying`；
`batch-topose.mjs` 把它写进 manifest 的 `flags: ['lying']`，画廊卡片显示「需手修」角标。

画廊里每张卡片右上角有 `✕`，可以把不满意的初稿**隐藏**（存 localStorage），
标题栏出现「显示已隐藏 (n)」可随时恢复——这就是"批量出初稿 → 人工筛选"的闭环。


> 精度预期：结构（坐/站/蹲、四肢大致朝向）可信 60~80 分；
> 躯干前后倾、手臂末端、脚掌朝向需要手动微调；手指和绕骨轴自转不可知。


### 构建产物只 1 MB（模型不进 dist）

`public/models/` 里有上百 MB 的第三方模型。默认 `vite build` 会把整个 `public/` 复制进 `dist/`，
每次构建白拷 100 MB、`dist` 也膨胀到 119 MB。

`vite.config.js` 里关掉了这个拷贝：

```js
export default defineConfig({ build: { copyPublicDir: false } });
```

静态服务器 `scripts/serve-dist.mjs` 按 **dist → public** 顺序回落，模型照常能取到：

```powershell
npm run build                    # dist 约 1 MB
node scripts/serve-dist.mjs      # http://127.0.0.1:5280/
```

> 构建用的打包器（rolldown）会派生子进程，在受限沙箱里会报 `spawn EPERM`——
> 在普通终端里跑没有这个问题。

## 姿势 JSON 格式（`vrm-pose/1`）

```json
{
  "format": "vrm-pose/1",
  "name": "招手",
  "meta": { "rig": "mannequin", "scaleHint": 1 },
  "hips": [0, -0.38, 0],
  "bones": {
    "leftUpperArm": [0, 0, 0.7934, 0.6088],
    "leftLowerArm": [0, 0, 0.2588, 0.9659]
  }
}
```

- `bones[骨骼名]` 是**四元数 `[x, y, z, w]`**，相对该骨骼的 rest 姿势；用四元数而不是欧拉角，避免万向锁。
- 骨骼名必须是 VRM humanoid 标准名（`hips` / `spine` / `leftUpperArm` …）。
- 单位四元数会被自动省略，所以 JSON 很小。
- `hips` 是相对 rest 的位移（米），可选。
- 模型缺少某根骨骼时**静默跳过**，并在状态栏报数量——这是跨模型复用的关键容错。

> 姿势数据一律写在 `humanoid.getNormalizedBoneNode(name)` 上，**不要**写原始骨骼；否则换模型就错乱。

## 直接加载 PMX（不需要先转 VRM）

three r187 已经移除了 `MMDLoader`，所以本项目**自己实现了 PMX 加载与骨骼重定向**（`src/pmx-loader.js` + npm 包 `mmd-parser`）。

### 三种载入方式（任选）

| 方式 | 适合 | 说明 |
| --- | --- | --- |
| **载入文件夹**（按钮） | 模之屋下载的模型 | 选**解压后的整个文件夹**，PMX + 贴图一起载入；浏览器里用 blob URL 解析相对路径 |
| **拖文件夹进画面** | 同上 | 拖拽时递归读取目录，效果一样 |
| `?model=/models/<目录>/<模型>.pmx` | 放在 `public/models/` 下的模型 | 贴图走 HTTP 相对路径 |

> 单文件「载入模型」只支持 VRM / GLB。PMX 的贴图是相对路径，单文件拿不到同目录的 `Texture/`，
> 所以选 .pmx 会提示改用「载入文件夹」。

```powershell
npm run dev
# 浏览器打开 http://localhost:5273/ ，点「载入文件夹（PMX + 贴图）」
```

它做的事情：

1. 解析 PMX（顶点 / 蒙皮权重 / 材质 / 798 根骨骼这类完整数据），构建 `SkinnedMesh`
2. 按 `flag & 1` 决定单双面，按贴图**实际 alpha** 决定是否 `alphaTest`（见下方坑）
3. 把 MMD 骨骼名映射到 VRM humanoid（`腕→leftUpperArm`、`ひじ→leftLowerArm`…，22 根全部覆盖）
4. 造一棵**标准 T-pose 的代理骨架**给 `pose.js` 用，每帧再重定向回 MMD 真骨骼

重定向的关键：MMD 模型多为 **A-pose**（这个模型手臂下垂 39°），而姿势数据是相对 T-pose 的。
所以每根骨骼要乘一个"绑定位姿校正" `C`：`目标世界朝向 = 代理世界朝向 × C`。
这样同一份 `vrm-pose/1` 既能驱动 VRM，也能驱动 PMX——**姿势数据仍然与模型无关**。

### 材质：MMD 贴图是"烘焙好光影"的，必须 unlit

最初用 PBR（`MeshStandardMaterial`）+ 全局 ACES 色调映射，结果整体发灰、脸发闷。
原因：MMD 的贴图里**已经画好了明暗**，再过一遍光照 + 色调映射等于二次压暗。
现在 PMX 默认走 **`MeshBasicMaterial`（不吃光照、`toneMapped = false`）**，直接输出贴图原色；
对比模式用 `?mat=toon`（色阶）和 `?mat=standard`（旧 PBR）随时切换。

配套的两个细节：
- **alpha-to-coverage**：有 alpha 裁剪的材质（发丝、蕾丝）打开它，配合 MSAA 把硬边缘磨平；
- 各向异性过滤 8x，斜视角贴图不糊。

### 描边与环境光

- **描边**用 three 自带的 `OutlineEffect`（反面外扩，支持蒙皮）。默认厚度 `0.005`（世界单位），
  `?outline=0` 关闭，`?outline=0.008` 自定义。五官/发丝这类小件与透明材质**不描边**
  （见 `pmx-loader.js` 里的 `NO_OUTLINE` 正则与 `userData.outlineParameters`），
  否则外扩出来的背面会把眼睛、嘴糊成黑块。
- **环境光为什么之前"没有"**：unlit 材质在定义上就不参与光照，所以场景灯光对它无影响。
  现在默认模式是 **`soft`**——`MeshToonMaterial` + 高下限色阶（0.85~1.0），
  既保留贴图原色，又能吃到一点方向光明暗；想要纯平就 `?mat=unlit`，想对比老 PBR 就 `?mat=standard`。
- 同时关掉了 PMX 网格的 `receiveShadow`：MMD 贴图自带明暗，再来自阴影会出现
  "头发在脸上投一道黑影"的脏效果（地面投影保留）。

### 球面贴图（SPH / SPA）

MMD 用"视空间法线"采样一张球面贴图来伪造反射——头发掠光、金属件反光、眼睛高光都靠它。
`mmd-parser` 里字段叫 `envTextureIndex` / `envFlag`（不是 sphere*）：

| envFlag | 含义 | 我们的做法 |
| --- | --- | --- |
| 0 | 关闭 | — |
| 1 | 相乘 | `diffuseColor.rgb *= 球面色` |
| 2 | 相加 | `diffuseColor.rgb += 球面色 × 强度` |
| 3 | SPA 叠层 | `+= 球面色 × alpha × 强度` |

用 `onBeforeCompile` 往 toon/standard 材质里注入一次采样（`vNormal.xy * 0.5 + 0.5`），
面板「高光」滑条实时调强度；`?sph=0` 关闭、`?sph=1.2` 加强。

> 坑：`src/pmx-parse.js` 早期只搬了材质的 5 个字段，`envTextureIndex` 没传下来，
> 球面贴图代码永远不触发（材质里 `envIdx` 恒为 -1）。补上字段后才真正生效。

### 接触阴影

方向光的投影只有轮廓，脚底是"飘"的。脚下加一张径向渐变的软阴影，
位置跟双脚中点走、大小按两脚间距；浓度由面板「接地」滑条控制（`?contact=0` 关闭）。
地面是深色时它只是一层轻微压暗——这是正常的，在浅色背景下最明显。

### 描边：屏幕空间恒定 + 按材质粗细

`OutlineEffect` 的顶点着色器是 `pos + normalize(pos - pos2) * thickness * pos.w`，
透视除法把 `w` 约掉，**本身就是屏幕空间恒定**的，不需要再按视距缩放。

真正值得做的是**按材质区分粗细**：PMX 每个材质都带 `edgeSize`（本模型里 11 个材质是 0.125、
40 个是 0.5）。加载时按模型内中位数归一化，面板的描边滑条作为基准，
于是细节件自动变细、衣装保持基准粗。

### 贴图格式：PNG / WebP / BMP / **TGA**

浏览器原生**不支持 TGA**，但异环、绝区零这类模型大量用 `.TGA` 做漫反射贴图。
`pmx-loader.js` 里自带一个 TGA 解码器（支持未压缩与 RLE、24/32 位、按 origin 位翻转），
解出来转成 `CanvasTexture` 再接进材质。

另外：**贴图加载失败时会退回材质的漫反射纯色**，而不是留一块黑色
（早期版本里 map 存在但解码失败，模型会整个渲染成黑剪影——就是这么来的）。

### 骨骼映射：按"谁真正驱动网格"选骨，不按名字

MMD 模型经常有**两套腿骨**：

```
动画骨：左足 → 左ひざ → 左足首      （IK/追加旋转驱动，名字最标准）
变形骨：左足02 → 左ひざD → 左足首D   （网格真正绑定的那一套）
```

只按名字取第一个候选（`左足`），就会出现**骨骼转了、腿一动不动**——因为这个模型里
`左足 / 左ひざ / 左足首` 上一个顶点都没有，网格全绑在 `左足02 / 左ひざD` 上。

现在的做法：加载时统计每根骨骼"支配"多少顶点（每个顶点取权重最大的那根），
在候选名单里**选实际驱动网格的那根**（`MMD_BONE_NAMES` 里同时列了 `左足`、`左足02`、`左足D`），
并把改判结果打到控制台：`[pmx] 按权重改映射: leftUpperLeg→左足02(178) ...`。

**还要再做一次"链一致性校正"**：D 骨里同一段肢体会有兄弟骨，例如

```
左足D ─┬→ 左足02    (158+188 顶点，看着像"大腿")
       └→ 左ひざD   (348 顶点，看着像"小腿")
```

只按权重选会把大腿选成 `左足02`、小腿选成 `左ひざD` —— 这俩是**兄弟**、互不影响，
大腿转一套、小腿转另一套，腿就被撕成两截、脚变成"芭蕾脚"。
所以选完之后从父到子检查：子骨骼若不是当前骨骼的后代，就换成能涵盖它的候选（这里换成 `左足D`）。

### 接地：按"蒙皮后的最低顶点"，不按脚骨

早期用脚踝/脚趾骨骼的世界 Y 当接地参考，结果**鞋底永远比骨骼低十几厘米**，
模型看起来"插在地里"；而且每次换姿势都在上一次的结果上再算一遍，误差累积、越点越沉。

现在 PMX 的走法是：换姿势后把**蒙皮后的全部顶点**在 CPU 上算一次世界 Y（46k 顶点，几毫秒），
取最低点贴到地面（留 4 mm 余量）。根节点最终落在 `y ≈ 0`，不会漂移。

> `Box3.setFromObject(mesh)` 对 `SkinnedMesh` 不可靠，别拿它算包围盒。

### 渲染调节（面板里可实时改）

左侧面板「渲染调节」这一栏，改完立刻生效，**存在 localStorage**，刷新后保留，换模型也不会丢：

| 控件 | 作用 | 调法 |
| --- | --- | --- |
| 描边（勾选） | 开关轮廓线 | 关掉就是纯色块 |
| 描边 | 粗细 0 ~ 0.012（世界单位） | 默认 0.0035；觉得糊就调到 0.002 |
| 立体 | 明暗下限 0.55 ~ 1.0 | **越大越平**（1.0 = 基本纯贴图色），越小越有体积 |
| 主光 | 方向光强度 0 ~ 3 | 决定明暗方向，太大会过曝 |
| 环境 | 半球光强度 0 ~ 2.5 | 整体提亮；>1.6 开始发灰 |
| 轮廓 | 背面补光 0 ~ 2.5 | 边缘更亮，立体感更强但不压暗主色 |

> 为什么"立体"是那样调的：MMD 贴图已经画好明暗，我们只在上面叠一层很窄的色阶。
> 下限越接近 1，越接近"原图直出"；越低，越像打了方向光。
> 这也是为什么它和"环境/主光"要一起调——只降下限不调灯，会整体变暗。

### 性能：贴图走 WebP，解析留在主线程

- **PMX 解析保持在主线程**。曾经试过放进 Web Worker（`pmx-parse.js` 拆成纯函数正是为此），实测
  **主线程 ~650 ms vs Worker ~850 ms**（多 200 ms 传输调度），总加载时间没有可测量的改善；
  而 `new Worker(new URL(...))` 会让 Vite 的 worker 插件在解析真实路径时 `exec` 子进程，
  受限环境里直接 `spawn EPERM`，dev 与 build 都会挂。**已回退**。
  （`pmx-parse.js` 仍是不依赖 three 的纯函数，将来需要时可再包一层 Worker。）
- **贴图**支持自动切 WebP：如果模型目录里有 `Texture_webp/`，加载器会探一次就整套用 WebP。
  维琳娜这套图用 ffmpeg 转完是 **12.5 MB → 0.9 MB（-93%）**，首屏那个 1.5 s 的长任务尖峰消失。
  转法见 `docs/PMX-to-VRM.md` 末尾，或直接：
  ```powershell
  ffmpeg -i Texture\脸.png -c:v libwebp -quality 82 Texture_webp\脸.webp
  ```
  `?tex=png` / `?tex=webp` 可以强制指定。

> 注意：总加载时间（2.6–3.7 s）的波动比这些优化本身还大，别用单次测量下结论。
> 客观收益是**体积 -93%**，以及**没有 1.5 s 的长任务尖峰**。

调试开关（URL 参数）：

| 参数 | 作用 |
| --- | --- |
| `?noskin=1` | 跳过蒙皮，直接渲染绑定姿势（隔离几何/材质问题） |
| `?noretarget=1` | 跳过重定向（看模型原始 A-pose） |
| `?mat=unlit` | **默认**：不吃光照，直接输出贴图原色 |
| `?mat=toon` | 卡通色阶（会二次压暗，仅对比用） |
| `?mat=standard` | PBR + ACES 色调映射（旧行为，偏灰） |
| `?mat=basic` | 去掉贴图/透明，纯灰材质 |
| `?mat=noalpha` | 保留贴图但关闭 alphaTest |
| `?mat=normal` | `MeshNormalMaterial`，纯看几何 |
| `?outline=0` / `?outline=0.008` | 关描边 / 自定义描边粗细（默认 0.005） |
| `?tex=png` / `?tex=webp` | 强制贴图格式（默认自动探测 `Texture_webp/`） |

## 已知坑（踩过的）

1. **首帧很慢，且极度依赖 GPU**：示例模型 10 MB，`GLTFLoader.loadAsync` 在 **CPU 软渲染（swiftshader）下要 53 秒**，换成 D3D11 硬件渲染只要 **3–4 秒**。所以做自动化截图验证时必须开 GPU（`--use-angle=d3d11`），否则会误判成"加载卡死"。
2. **Vite dev server 首次请求很慢**：要现场预打包 three（700 KB / 600+ 模块），冷启动那次请求能占住几十秒，`domcontentloaded` 都等不到。自动化验证建议用 `npm run build` + `scripts/serve-dist.mjs` 走纯静态服务。
3. **three r187 的两个 API 变化**：`THREE.Clock` 已废弃（改用 `performance.now()` 自己算 dt）；`PCFSoftShadowMap` 已移除（用 `PCFShadowMap`）。
4. **`SkinnedMesh` 不能用包围盒剔除**，姿势一改就会被裁掉；加载后统一 `frustumCulled = false`。
5. **取景不要用 `Box3.setFromObject`**：它算的是绑定姿势的包围盒，不是蒙皮后的形状；本项目改用骨骼世界坐标取景。
6. **`VRMUtils.combineSkeletons` 对带约束的模型可能抛错**，已用 try/catch 兜住，失败不影响加载。

### PMX 专属的四个坑（都踩过）

7. **`mmd-parser` 的 `material.faceCount` 是"三角形数"，不是索引数**。拿它当 `addGroup` 的长度会让每个材质画到别人的三角形上，模型看起来像被撕碎——索引数要 ×3。
8. **不能一刀切 `alphaTest`**：MMD 的脸/发贴图带 alpha（需要裁剪），身体/衣服贴图不带（裁剪会把面片吃掉）。最初统一 `alphaTest: 0.35` 导致整个模型只剩几块碎片。现在的做法是加载贴图后采样 alpha 通道，只有"确实含透明像素"的才开 `alphaTest: 0.5`。
9. **缩放要烘进顶点和骨骼坐标**，不能给父级加 `scale`：`SkinnedMesh` 的 `bindMatrix` 在 `bind()` 时就固定了，父级缩放会被算两次。MMD 单位约 1/8 米（这个模型 21.7 单位高），按目标身高 1.6 m 烘焙。
10. **`Skeleton` 必须在骨骼世界矩阵就位之后创建**（`mesh.updateMatrixWorld(true)` → `new Skeleton(bones)` → `bind()`），否则逆绑定矩阵全是单位阵。
