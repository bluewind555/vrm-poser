# PMX → VRM 转换清单

你没有 VRM，只有模之屋的 PMX/MMD 模型——这个转换是当前**唯一的关键路径**，网页端代码已经就位。
下面按"先决条件 → Blender 操作 → 验收"的顺序写，重点标出会返工的地方。

---

## 0. 先确认授权（30 秒，但能省掉几天的白工）

模之屋的 MMD 模型绝大多数带**配布条款**，常见约束：

- 仅限个人非商用
- **禁止再配布**原始或修改后的数据
- 禁止用于特定平台/特定用途（R-18、政治、商用游戏等）
- 部分要求转载时附带作者与原始链接

把模型转成 VRM 再放到网页上，**通常已经构成"再配布"**（VRM 是包含网格、贴图、骨骼的完整可分发资源）。
要做公开站点，先找到原模型的 `readme.txt`，确认三件事：能不能改、能不能转格式、能不能公开到网页。
只做本地/自用演示，风险低得多。

---

## 1. 环境

| 组件 | 版本 | 备注 |
| --- | --- | --- |
| Blender | 4.x（3.6 也可） | 官方安装包即可 |
| `mmd_tools` | 随 Blender 插件市场装 | 读 PMX/PMD、处理 MMD 材质与物理 |
| `VRM_Addon_for_Blender` | 2.x（支持 VRM 1.0） | <https://vrm-addon-for-blender.info/> 或 GitHub 官方仓库 |

两个插件都要在 `编辑 → 偏好设置 → 插件` 里启用。

**建议先导出 VRM 0.x 还是 1.0？** 选 **1.0**。本项目的加载路径对 0.x 也做了兼容（`VRMUtils.rotateVRM0`），但 1.0 的归一化骨骼语义更干净，且是当前生态主流。

---

## 2. 导入 PMX

1. `文件 → 导入 → MMD (.pmx)`，勾选**骨骼**与**材质**，物理可以先不导（后面重建）。
2. 导入后模型可能极小或朝向奇怪：用 `N` 面板看缩放，MMD 单位是 1/8 米左右，常见需要 ×0.08 或 addon 自动处理。
3. **检查朝向**：VRM 1.0 要求模型面朝 **+Z**。mmd_tools 导入后一般面朝 -Z（MMD 是左手系），在 Blender 里绕 Z 转 180°。
4. `物体 → 应用 → 全部变换`，避免导出时带着非单位缩放。

---

## 3. 重命名骨骼（最容易返工的一步）

VRM 插件认的是 **humanoid 标准名**，MMD 的日文骨骼名它一个都不认识。
在 Blender 的骨骼编辑模式下，用 `F2` 逐根改名，或写个简单的 Python 脚本批量改。

### 标准映射表（VRM 1.0）

| MMD 骨骼 | VRM humanoid | 说明 |
| --- | --- | --- |
| 全ての親 | —（不映射） | 导出时忽略，或作为根节点保留 |
| センター | —（不映射） | VRM 没有对应骨骼；见下方层级说明 |
| 下半身 | `hips` | 关键：**让 hips = 下半身** |
| 上半身 | `spine` | |
| 上半身2 | `chest` | 没有这根就用 `spine` 顶 |
| 上半身3 | `upperChest` | 少见，有则映射 |
| 首 | `neck` | |
| 頭 | `head` | |
| 肩.L / 肩.R | `leftShoulder` / `rightShoulder` | |
| 腕.L / 腕.R | `leftUpperArm` / `rightUpperArm` | |
| 腕捩 | —（删除或合并） | 扭转骨，VRM 无对应；建议直接删掉并把权重合并到腕 |
| ひじ.L / ひじ.R | `leftLowerArm` / `rightLowerArm` | |
| 手首.L / 手首.R | `leftHand` / `rightHand` | |
| 足.L / 足.R | `leftUpperLeg` / `rightUpperLeg` | |
| ひざ.L / ひざ.R | `leftLowerLeg` / `rightLowerLeg` | |
| 足首.L / 足首.R | `leftFoot` / `rightFoot` | |
| つま先.L / つま先.R | `leftToes` / `rightToes` | 没有就留空，本项目会自动跳过 |
| 指（親指0/1/2、人指1〜3、中指、薬指、小指） | `thumbMetacarpal` … `littleDistal` | 可选；不做手指动作可以整组不映射 |

### 层级必须改

MMD 的层级是 `センター → {上半身, 下半身}`，两条链并列；VRM 要求 `hips` 是根，`spine` 和两条腿都在 `hips` 下面。

改法：

1. 把 `下半身` 改名为 `hips`
2. 把 `上半身` 的父级设为 `hips`
3. 确认 `足.L/R` 的父级是 `hips`（mmd_tools 导入后本来就是下半身的子级，通常不用动）
4. 删除 `センター`，或把它保留为骨骼根（VRM 导出会忽略非 humanoid 骨骼）

如果层级错了，导出时插件会报 "Required bone not found" 或导出的模型一动腿就断开——这是最常见的返工点。

### 手指可以放弃

第一版只做躯干 + 四肢 + 头就够用。手指不映射不影响导出，只是姿势里不能摆手指。

## 4. 材质

MMD 的 toon 材质（`.sph` / `.spa` / toon 贴图）在 Blender 里会变成一堆节点，VRM 1.0 只认 **MToon** 或 PBR。

务实做法：

1. 每个材质改成一个 **Principled BSDF**，基础色接贴图，Metallic 归 0，Roughness 0.6~0.9
2. 有透明部分的（头发、裙边）勾上 `Alpha` 混合，设置 `Alpha Clip` 阈值
3. 背面剔除：MMD 模型常是单面，导出前在材质里关掉 "Backface Culling" 会导致 VRM 里透光，需要按需开
4. VRM 插件导出时会把这些转成 MToon（或 `VRM 1.0` 的 unlit 材质），阴影色会自动算

> 不追求还原度的话，Principled 直接出效果就能看，别在材质上耗太久。

---

## 5. 物理与表情

- **物理（裙摆/头发/胸部）**：MMD 刚体+关节**不能**直接转 SpringBone。要么在 VRM 里用 SpringBone 重建（VRM 插件有 SpringBone 面板），要么第一版直接跳过——静态姿势展示不需要物理。
- **表情**：MMD 的 morph 需要手动映射到 VRM 的 expression（`happy` / `angry` / `blink` …）。第一版也可以跳过。

---

## 6. 导出与验收

1. `文件 → 导出 → VRM`，选 VRM 1.0
2. 插件会检查 humanoid 骨骼是否齐全，缺 `hips`/`spine`/`head` 会直接拒绝导出
3. 导出后**立刻**自检：

```powershell
cd vrm-poser
# 把导出的 .vrm 放进 public/models/
npm run dev
# 浏览器打开 http://localhost:5273/?model=/models/你的模型.vrm
```

验收清单：

- [ ] 模型正常显示，比例不是巨人/蚂蚁（否则是单位没应用）
- [ ] 面朝镜头（否则朝向没转）
- [ ] 点"自然站立"预设，手臂下垂方向正确（不正确的常见原因：左/右骨骼接反了）
- [ ] 点"接地校正"，脚底贴地、不穿地
- [ ] 拖动"髋部高度"滑条，整个人上下移动而不是腿被拉长

## 7. 出问题时的排查顺序

| 症状 | 大概率原因 |
| --- | --- |
| 导出被拒："bone not found" | 骨骼没改名，或层级不对（`spine` 不在 `hips` 下） |
| 加载后是空的 / 只看到头发 | 材质全透明，或 `frustumCulled` 把网格裁了（本项目已统一关掉） |
| 手臂摆成奇怪方向 | 左/右骨骼映射接反，或 `腕捩` 没删 |
| 摆姿势时腿断开 | `hips` 的父子关系没重设 |
| 模型朝向背面 | 没转 180°（VRM 1.0 面朝 +Z） |
| 贴图全黑 | 材质没接贴图，或颜色空间不对（贴图需要 sRGB） |

---

## 8. 一个更省事的替代路线

如果转换卡住超过一天，考虑直接找**现成的 VRM 模型**：

- [VRoid Hub](https://hub.vroid.com/)：大量免费/可商用 VRM，授权写得很清楚
- BOOTH 上的 VRM 素材（多为原创角色，条款比 MMD 模型宽松）
- 用 **VRoid Studio**（免费）捏一个角色，直接导出 VRM——10 分钟就能拿到一个可用的测试模型

对"验证姿势管线"这个目标来说，先拿一个 VRoid 角色跑通，比啃 MMD 转换划算得多。
